# 消防物联网平台（Ubuntu/Linux）

本项目是低配单机优先的自托管消防平台。构建、运行和测试使用 Ubuntu/Linux；Windows 开发机通过 WSL 2 运行。服务器部署、数据库和备份要求见 [Ubuntu 部署手册](docs/ubuntu-deployment.md)。

## 当前范围

| 能力 | 边界 |
|---|---|
| 双端与身份 | 管理端/客户侧、单位grant、显式权限与强制改密；普通增改直接保存，重要操作二次确认但不重复输入操作密码；不默认扩客户权 |
| 产品、设备、参数 | 发布版本绑定、设备开户/迁移、参数分层与实际消费者；连接、物理及接入状态独立，不以接收时间推测在线 |
| 真实接入 | 旧烟感由网关/运营商直接上报（保留原转发入口）、海康推送与补拉、通用鉴权消息与自动应用；新增/关联及控制按各来源实际能力与回执，不把接收或轮询时间冒充设备上报 |
| 报警与通知 | 真实事件轨迹、复核/处置、真实短信/语音通道与显式收件升级规则；供应商结果据实记录，不伪造送达 |
| 管理工作区范围 | 左侧单位/位置树只收窄读取，不授予权限。已取消顶部操作单位与全局隐式目标；已有记录按实际归属操作，新建在表单内确认目标，单一范围可一次性预填，后续筛选不改写草稿。多单位不得猜第一行；逐请求授权、CAS与未知结果保护保留 |
| 变更信号 | 对象变化只触发有权HTTP重读，不直接patch业务状态；客户报警保留5秒HTTP补查，WS ready也不停止。管理单单位信号不冒充跨单位流 |
| 设备分组 | 按实际归属单位维护扁平多对多关系，管理端创建/编辑/逐台加入移出、客户只读；独立组revision，不授予权限 |
| SIM手工台账 | 管理端当前授权单位建档/编辑、分页/详情及不可变维护快照；独立读写权、当前会话/CAS/原key幂等；未知维度不推断，无运营商同步/计费 |
| SIM平台关联（P9a2本地有限验证完成） | 一机一卡、显式绑定/解绑、独立关联revision/不可变历史；三权与当前会话、原key重放及未知结果屏障；不推物理插拔/库存/在线/运营商事实 |
| SIM内置人工资料与人工库存（P9a3/N02本地有限验证完成） | 内置卡资料归属已有设备、ICCID可未知；可插拔卡入库/领用/回收/报废直登、无审批，去向为普通文字，解绑不回库、回收可用、误报废凭依据更正且保全部记录；不另造绑定、不推物理/运营商/盘点事实 |
| SIM到期站内提醒（N03本地有限验收完成） | 独立规则、显式平台收件范围、日历到期轮次、个人已读与整轮处理；初始关闭且无有效默认规则，自动扫描不改SIM资料或物理/运营商事实 |
| 资产与身份运营 | 单位→位置树→设备；角色决定动作，ALL_TENANT/DEVICE_SET/PLACE_SUBTREE分别决定全单位、指定设备或动态位置子树范围。位置内后续新增设备自动进入子树范围，移出自动失去可见性；分组不授权。用户资料和有效期独立于角色与范围，已移除值守人员概念，历史处理人与负责人保留 |
| 通用数据操作 | CSV/XLSX模板、预检、逐行任务、失败行、取消/重新确认及按范围导出；计划和导出文件加密保存，读取仍核验当前权限 |
| 单位自助与海康配置 | 客户端维护已授权的本单位离线阈值、联系人及FIRE/FAULT收件策略；管理端页面维护海康凭据与轮询配置，Secret仅写入 |

具体合同/功能边界在[路线图](<docs/roadmap.md>)、[实现说明](<IMPLEMENTATION.md>)及[后端](<backend/README.md>)/[前端](<frontend/README.md>)。数值参数沿集中配置与实际消费者规则，不新增无效设置；分组不是授权或在线指标。

多厂商、多产品设计见[目标架构与实施方案](docs/iot-platform-architecture.md)。设备能否提供原始心跳、远程配置或硬件控制，按实际来源分别验收。正式部署使用站点独立配置，不在公开源码中维护站点地址或运行记录。

隔离软件验证、生产只读观察、真实设备上报与恢复、厂商写入、短信/语音送达、支付分别记录，不能相互替代。现有数据、密钥及真实业务库的保全边界以每次发布证据为准。
### 当前操作导航

- **登录**：用户端经 HTTPS 登录后，同一标签页刷新可恢复原会话。刷新不延长有效期；退出、改密或服务端撤销后须重新登录。管理端仍使用独立登录入口，刷新不恢复会话。
- **组织与权限**：先建单位和位置，再建用户并配置角色、动作权限与设备范围；权限和数据归属是两回事。管理端左侧单位/位置树默认收起，展开或收起不会清空当前筛选；它只过滤读取，不能决定新增或改写的目标。创建、移动等操作要在表单中明确目标；既有记录始终按其实际归属操作。
- **设备资产**：设备资产→新增设备，可直接填报旧烟感本地资产或海康云新增；均须明确实际单位与位置，海康新增会产生云端写入。批量导入在同一入口提供两套来源模板：旧烟感模板按行在本平台新建，海康模板只关联已发现的海康设备，不是云端批量开户。先预检/核对，再确认导入；普通资料编辑直接保存，移动、归档等按目标与影响确认。归档保留历史，不等于厂商删除；重建旧烟感资产会产生新资产身份，只有真实新上报才构成激活/恢复证据。
- **导出设备资产**：设备资产 → 设备工具 → 导入 / 导出 → 导出设备资产。默认 Excel，按文本保留设备编号的前导零和全部位数；表中使用正式型号、产品及归属名称、中文状态和北京时间，不显示数据库 ID 或版本 UUID。可按范围、筛选及勾选导出；该表不是导入模板。
- **现场维护**：管理端「事件与处置 → 维保工单 → 现场维护清单」查看现场处理或更换记录，无需逐台建工单。新机沿用旧机归属，确认接入后才允许归档旧机；海康换机还需核实旧机云端结果。清单保留操作人、时间、位置和旧设备历史，不据人工处理推断设备恢复。
- **旧烟感下拉 Excel 模板**：设备资产 → 批量导入设备 → 下载 Excel 模板（带下拉）。在「设备」表逐行选择归属单位、该单位内的安装位置和设备型号，手填设备名称、机身标识；安装地址和不同于机身标识的上报标识可留空。每份文件限一个单位，单位可向下填充；更换单位后须重选位置。上传后核对表内归属，无需在网页重选。已下载的「归属设置」版仍可上传；更早的 XLSX、CSV 在「旧模板与 CSV 选项」选择单位并导入。
- **旧平台 Excel 原模板**：设备资产 → 批量导入设备 → 选定目标单位后，直接上传「无线终端批量导入模板.xls」。仅读取「终端设备」页；同一表可混填型号和位置。按每行旧产品全名识别解析定义，有归档映射时核对「平台」列，同名产品可用该列区分。所属位置使用本单位内位置名称或 `上级 / 下级` 完整路径。无法匹配或标识冲突会报 Excel 行号，设备编号等身份列须以文本保存。预检不写入；确认后整批建档，不修改旧平台或网络配置。旧入网密钥、安装人和 GPS 不随设备导入。
- **设备状态**：未收到过有效上报为未激活；超时但没有独立周期上报证据时，不判定为离线。超时阈值按单设备 → 设备分组 → 最近配置的位置 → 单位 → 全局取值，同设备多个组设了阈值时取较长值；详情显示生效来源。分组关系不授予设备权限。连接状态、物理状态、人工处置互相独立。
  客户端只显示最高优先级状态；管理端另显示独立在线状态及业务状态。离线覆盖客户端标签，不取消事件、处置或通知。火警默认穿透通知屏蔽；仅明确涵盖火警且正在生效的屏蔽规则才覆盖火警。通知屏蔽不等于设备本体禁用，厂商 API 受理也不代表本体状态已确认。
- **事件与处置**：「当前报警事件」切换报警和当前故障；「报警历史」「故障历史」均可按事件或设备查找；「报警归并」内查看记录和设置归并策略。人工处理不等于设备恢复。
- **通知与费用**：通知联系人、FIRE/FAULT规则与短信/语音通道分开配置。短信条数和语音次数独立计量、余额不互抵；通知记录中的`ACCEPTED`仅代表服务商受理，不是送达或接听；`UNKNOWN`结果不自动退费或重发，`REJECTED`表示明确拒绝。测试软件不证明外部送达。
- **客户端语音短信充值**：在「我的充值订单」打开本人待支付的微信订单，选择「取消支付」并确认。微信要求订单创建至少 5 分钟才能关单；关单结果未确认时暂停显示付款码，用「核对取消结果」查询原订单，不重新发起关单。查实已支付的订单正常入账，不走取消或退款。「关闭详情」只收起页面。
- **导航**：管理端为总览、设备与接入、事件与处置、组织与权限、通知与费用、系统设置。不按基础/值守服务分组；核心入口常显，点击分组可展开低频功能，也可按页面名搜索。客户端为首页、设备、报警、我的。页面可见性仍受会话权限控制。
- **接入与文件**：「接入来源」「消息追踪」用于通用 HTTP 入站；旧设备到「接入镜像」，海康到「海康云接入」。不向第三方推送数据，各业务页的文件导出及「导入与导出」仍可用。「数据保留」按单位和数据类型配置，支持先试算；没有启用的策略不会自动清理。

## Ubuntu工具与构建

要求 Java 21 JDK、Maven 3.9.11、Node 24 和 Python 3.12+。本地开发默认 H2；生产使用独立 PostgreSQL 17。开发脚本不自动安装或操作系统服务。

已有Linux工具可直接使用`JAVA_HOME`/`PATH`。也可准备经发布方checksum核验的项目本地工具：

```bash
bash scripts/prepare-tools.sh
bash scripts/package.sh
```

本地二进制只放忽略目录`.tools/linux`，入口自动加载，不改系统PATH或用户配置。完整交付运行`package.sh`，包含前后端测试、前端构建和资源嵌入。仅验证时用`bash scripts/verify.sh`，不要例行串行运行两者。只有 `frontend` 和 `scripts/codec-sandbox` 的依赖都已按各自锁文件安装时才用 `--skip-install`；它不跳测试。后续变更遵循[项目变更规则](AGENTS.md)。

输出`backend/target/fire-platform-backend-0.1.0-SNAPSHOT.jar`，运行应用不需要常驻Node。生成目录和工具不入库；源码行尾由[Git属性](<.gitattributes>)统一LF。不要把已归档旧包当作迁移后当前构建。

## 开发启动

```bash
export APP_PROFILE=dev APP_STORAGE=h2-dev APP_BOOTSTRAP_USERNAME=admin
read -r -s -p '初始密码（至少 6 位，数字／字母／符号至少两类）: ' APP_BOOTSTRAP_PASSWORD; printf '\n'
export APP_BOOTSTRAP_PASSWORD
# 真实接入开关默认关闭；配置来源凭据及明确归属后按环境模板启用。
bash scripts/run.sh
```

默认仅回环8080，首次登录强制改密；已有用户不会被bootstrap密码覆盖，无内置默认密码。不再默认创建业务单位、客户或设备。H2开发数据放后端相对数据目录，重启保留。环境变量见[模板](<.env.example>)，脚本**不会自动source密码文件**。

管理端与用户端的新建账号、改密和重置均要求密码至少 6 位，数字、字母、符号至少使用两类（空格不计为符号）。现有密码不因规则变更而失效。

## Ubuntu部署

正式生产使用独立 PostgreSQL 17 库和最小权限账号，设置 `APP_PROFILE=prod`、`APP_STORAGE=postgresql` 及 `APP_DB_URL/APP_DB_USERNAME/APP_DB_PASSWORD`。真实接入、付费通知和变更信号按各自配置明确启用；应用不自动部署或重启既有服务。单节点 PostgreSQL 不等于高可用。

按[Ubuntu部署手册](<docs/ubuntu-deployment.md>)配置非root systemd服务、独立数据目录、私密环境文件、反向代理/TLS、备份和真实恢复演练。`api`/`worker`共享同一PG；当前分机/HA尚未验收。仅在显式启用通道时配置精确Origin，单API或可靠粘性路由；不把head传输当无漏报保证。H2不得用于多进程生产共享库。

## Linux验收夹具

当前活动业务验收入口为隔离身份HTTP夹具及其浏览器辅助程序。模拟执行和依赖默认业务种子的旧验收链已归档至`artifacts/retired-simulation-tooling-20261110/`，仅供历史审计，不能继续作为当前验收入口。这些夹具不连接或重启已有数据库。

在仓库根目录执行；直接运行Python/Node夹具前，将本地工具只加载到当前shell（不写用户profile、不加载私密配置）：

```bash
ROOT=$PWD
source "$ROOT/scripts/runtime-env.sh"
python3 scripts/identity-smoke.py
# 可选PG17私有测试工具：只下载校验并解包，不创建系统服务。
python3 scripts/ubuntu-download-pg.py --tools "$PWD/.tools/linux"
bash scripts/prepare-postgres.sh "$PWD/.tools/linux/downloads/embedded-postgres-binaries-linux-amd64-17.11.0.jar" 0dd7b72b6f335b8ecfb355fa24c5781e8a93edd09880bb77eb52ebbf29b3e96d
python3 scripts/identity-smoke.py --storage postgresql
```

需要浏览器时，先阅读`identity-smoke.py --help`并准备项目浏览器模块及明确的Ubuntu Chrome/Chromium路径。浏览器、JVM、私有PG只能由夹具有限启动并结束；凭据仅env/私有stdin，不写参数/报告。归档模拟链不代表真实设备、供应商通知、硬件或生产验收。
