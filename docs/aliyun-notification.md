# 阿里云短信/语音报警通知

## 当前状态与安全边界

本页描述当前真实通知实现，不是生产启用/发送操作手册。不得为文档验收启用真实通道、调用会产生费用的供应商接口、变更现有测试收件限制，或覆盖已有 MQTT/真实渠道配置。生产环境当前状态与实际投递须由父级补充部署及运行证据；代码存在真实 provider 不等于已配置、已发送或已送达。

发送总开关 `fire.notification.real-enabled` 默认 `false`。阿里云凭据、签名和模板可从 `fire.notification.aliyun.*` 配置；通知 provider 配置也由全局管理 API 持久化，读取/更新端点为 `GET/PUT /api/management/notification-provider`，状态端点为 `/status`。该配置需 `notification-config:read` / `notification-config:write` 管理权限，不能带 `X-Tenant-Id`；密钥存储密钥须由部署方安全提供。敏感配置仅保留掩码展示，禁止打印或提交任何凭据。

## 真实通知条件与路径

非模拟 `FIRE` 报警和已保存订阅证据的真实 `FAULT` 事件共用规则、联系人、短信/语音资源及供应商尝试记录。火警须仍处于 FIRE、未被人工处置或抑制；设备型号与事件订阅、单位/位置通道策略、真实通知总开关及供应商凭据仍分别校验。FIRE 事务提交后立即唤醒发布及指定报警通知，不等待 5 秒扫描；镜像原文落盘和海康回调提交后也立即唤醒解析。默认每 5 秒扫描仍作为恢复兜底及 FAULT 的发送入口，首次延迟 15 秒；每轮各最多 20 条火警和故障。立即触发不是运营商送达时限承诺，运行状态不是送达证明。

首次没有持久化 cursor 时，以 worker 启动时的数据库时间建立历史下界；启动后、首次扫描前的首条 FIRE 仍可立即派发，FAULT 在首轮扫描处理。已有 cursor 保留原边界，不借本次修复重发旧历史。联系人创建、详情、保存及客户单位列表统一返回实际单位信息，避免写入成功后前端将回执误判为失败。

通知首次启用时保留源事件时间下界，不自动补发此边界之前的历史。`cursor` 此后固定为该下界，不再因处理较新的事件向前跳过迟到事件；数据库 `real_notification_completions` 按单位、来源类型和来源记录标记首轮扫描完成。相同发生时间超过单页、启用后迟到的事件继续进入后续轮次；等待升级的事件不阻塞本轮其他事件。升级保留原 cursor 作为切换边界，不自动重放旧边界之前的记录。完成扫描不等于发送成功，具体结果仍以尝试、抑制、资源和回执记录为准；UNKNOWN 不因此自动重发。迁移 V88 仅新增完成标记表，不启用通道或补发历史。

短信和语音通道独立配置、计量、计价及入账，余额不互抵。真实规则以 `event_scope` 分别维护 `FIRE` 和 `FAULT`；接收者引用本单位联系人，不使用退役的模拟模板。每个渠道等级从1连续递增，最多5级；短信与语音分别配置0至60分钟升级间隔。单级规则的间隔必须为 null/0；多级间隔按渠道应用。阿里云短信模板 Code 来自真实 provider 通道配置，不从旧本地模拟模板取得。

周期提醒以本轮已完成为准，不等待所有通道均受理。等待升级以及明确失败的有限重试继续在本轮执行；策略禁止、无接收人、尝试耗尽、结果不明不堵住下一个定时周期。只有实际持久化的受理尝试才更新最近受理时间。同一轮 UNKNOWN 不重发、不自动返还额度；下一轮只能在已配置的周期到期后按当时的告警状态与策略评估。

真实规则 API：`GET /api/management/notification-rules`、`GET /api/management/notification-rules/{id}`、`POST /api/management/notification-rules`、`PUT /api/management/notification-rules/{id}`。创建/编辑使用 `notification-config:write`、变更原因及幂等键，不重复输入操作密码；更新带 `expected_revision`。读写字段包含 `name`、`enabled`、`receivers`（`channel` 为 `SMS`/`VOICE`、`contact_id`、`level`）、`sms_escalation_interval_minutes`、`voice_escalation_interval_minutes`。列表与详情只呈现 `legacy_mode IS NULL` 的真实规则；旧模拟规则留作历史，不能自动转为真实规则或纳入真实发送。

## 尝试、回执与不确定结果

每个收件渠道的外部调用会记录 provider attempt 和本地 spool 状态。`ACCEPTED`表示供应商已受理请求，不证明短信送达、语音接通或听完；`UNKNOWN`表示受理结果无法确定，禁止自动重试，也不自动退费，避免重复发送、重复扣减或错误冲账；`REJECTED`表示供应商明确拒绝，依尝试记录区分是否产生资源扣减。只有已关联并验证的供应商回执证据可确认进一步结果，未取得时保持未确认。当前代码及隔离测试不代替受控号码的真实发送、接收与计费验收。

`POST /api/management/notification-provider/test` 是会向指定号码发起真实 provider 请求的有副作用接口，不是模拟验收接口；未经明确授权、费用确认和受控测试号码许可，不得调用。全局 `test_mode_enabled` 会把真实告警流量重定向到已配置测试号码，绝不可为一般验收启用或解除既有限制。

## 后台自助验证顺序（2026-11-16）

单位、位置和客户用户由使用者在后台自行创建，不要求先把设备或手机号交给开发人员代填。创建客户用户后，另在“角色 / 设备范围”授予本单位全部设备或明确设备集合，并授予报警读取、复核，按需授予报警历史、设备读取；首次登录须改密。

手上已有的旧平台设备先在设备台账精确查找，已经导入的不重复新建；需要跨单位时使用“跨单位移交”，同单位调整使用“移动位置”。真正未登记的旧来源设备可使用台账“新增设备”或对应批量模板。海康未关联云设备可在同一新增表单填写精确序列号，或使用“发现与归属”；已经关联但在“未分配”的设备走跨单位移交，可直接指定真实目标单位和位置，无需捏造来源位置。移交保留来源历史、别名与海康关联，并继续校验目标位置、权限、版本及待处理消息边界。

在“通知联系人”相关表单明确选择目标单位，分别配置联系人、`FIRE` 报警/`FAULT` 故障通知规则以及短信/语音通道策略；两个渠道分别选择有效联系人。左侧单位/位置树只是读取筛选，不是写入目标。再检查“报警基础配置”的订阅、接收与推送条件，以及“通知资源”中该单位各渠道的独立余额；旧单位余额不自动转给新单位。

在管理端维护“报警与故障通知规则”时，选定单位后，规则表单和“设备生效联系人”按当前服务端设备范围提供目标。全单位设备范围可配置单位、位置或设备规则；仅有部分设备范围时，只能选择有权访问且未归档的设备，不能写单位或位置规则。有通知权限但无可用设备范围时，不可新建规则或预览；已有可读的规则仍可查看。编辑固定在规则原目标，保存时服务端重新验证。单位规则仍需同时配置短信和语音；位置或设备规则至少配置一个渠道。预览按设备及 `FIRE`/`FAULT` 计算，不发送通知或扣量。

“通知通道”中的短信、语音开关独立控制运行客户端；配置事务提交后才公布至客户端，回滚不更换运行凭据。关闭后不发送，也不为已知未就绪渠道产生消费/退款流水。关闭不会清除数据库模板或历史回执查询凭据，语音不再依赖短信签名和短信模板；持久配置无法读取时禁止退回环境中的发送能力。已有在途供应商请求无法通过关闭开关撤回。

生产既有通道与受控号码设置不得因软件验收而变更。受控号码覆盖只替换已经匹配接收资格的短信/语音目标，不新增接收资格，也不把未配置联系人的设备变成可发送。关闭覆盖前仍须核对真实单位、联系人、规则和通道，避免将测试转为面向实际联系人的发送。无明确授权不执行真实发送。

通道发送测试仅校验指定号码的供应商调用，可能产生供应商费用，不代表报警规则、单位余额或客户端处置链已经验收。最终由使用者在两个来源各选一台真实烟感，按厂商允许方式触发报警；核对真实上报、短信/语音接收、客户复核、发送记录及各渠道资源流水。海康恢复须核对真实来源恢复记录；旧来源没有已证实的通用恢复码时明确保持未恢复，普通心跳、人工复核和等待超时都不冒充恢复。供应商受理不等于送达。
